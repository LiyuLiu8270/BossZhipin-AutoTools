# 1.3.1 启动生命周期与退出诊断

## 背景

2026-10-03 16:39:32（北京时间）托盘最后记录服务无响应；16:39:34–35 Windows记录安装OpenAI.Codex更新及沙箱服务重装。后台、托盘、采集日志此后均中断，库中仍有运行中检查点，未见正常收尾记录。高度相关，但无进程终止审计，不能断言更新就是唯一原因。

## 优化

- 开发便捷入口npm start向Windows Explorer提交原生EXE打开请求。用户也可在资源管理器中双击EXE。保留原单实例互斥、端口鉴权，不新增计划任务/系统服务，不修改作业对象、安全策略或权限。
- 使用独立安装的Node优先于继承PATH；版本检查仍要求24+。
- desktop.log记录托盘启动、状态变化、服务启动PID/Node路径、退出码和托盘退出。
- service-lifecycle.jsonl由后台直接写入：process_start、service_ready、stop_requested、shutdown_complete、process_exit及fatal_error。不保存提示词、错误消息正文、账号、Cookie或模型密钥。
- 强制终止/断电可能来不及留下退出事件；缺少退出事件不等于已定位终止者。仍需Windows日志交叉判断。

## 验证和边界

scripts/verify-desktop-lifetime.mjs用隔离GUI测试程序验证：其父进程为explorer，Node启动器已退出，测试程序仍持续心跳，然后通过测试专用停止文件正常退出。未关闭/更新真实Codex，未发送HR消息，也不保证操作系统强制结束、关机等情况下持续运行。

托盘不会无限自动重启服务；任务进度依旧由现有SQLite恢复规则处理，未知发送不自动重发。原业务策略和配置保持不变。发布前正常停服、备份，再切换托盘，不强杀模型进程。

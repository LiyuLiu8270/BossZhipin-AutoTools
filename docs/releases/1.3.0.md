# 1.3.0：先取得工商全称再背调

新岗位在详情采集时，直接从可见工商信息区读取“公司名称”，保存为独立的 company_identity，不覆盖招聘显示名。保留来源岗位 URL、时间、字段原文和关联公司主页；不会把正文、推荐公司或法人姓名当成企业名。多主体冲突不猜。

背调优先复用30天内的同岗位证据，不额外打开公司主页。历史岗位缺全称则访问已有的关联公司主页，从企业名称、信用代码及注册地址取证；主页按URL缓存，单路打开自有页面，与岗位采集错峰。正结果缓存30天，页面明确无信息缓存1天。登录、验证、页面离开和连接失败有退避，不解验证码，不重放内部接口。

模型检索使用全称和工商证据；无法取得或存在冲突时不调用模型、不计模型任务额度。浏览器等待仍占用背调在途槽，完成后释放，不突破全局上限。界面可查看全称、信用代码（若页面展示）、来源及采集时间。

新增 company_identity 缓存表；不修改岗位表结构、不清除人工记录。背调版本键升级到 v3，旧简称报告留存在数据库但不自动复用，新队列按现有值得沟通范围重新建立，会产生新的背调请求和额度消耗。现有开关、总并发、每日额度不改变。缺公司主页且未采得详情证据的历史岗位暂待核实，未强制全库重采。

工商全称来自招聘平台展示，不等同于官方登记查询或最终劳动合同签约主体；外部资料仍需引文核验。平台访问受限时保留未知，不通过搜索猜全称。

# 1.3.2 页面响应优化

日期：2026-10-07。

## 修复

多路空队列检查此前在await之后才发布无任务结果，同一轮可能重复扫描16遍；空队列缓存使用全库变更代数，采集进度等无关写入也会令缓存失效。改为同步领取/同步发布空结果，随后才进入异步模型任务。缓存按相关表、资料和策略变化失效，并保留5秒时间重查。

招呼领取时直接在SQL过滤完成、运行中、失败、未到期或耗尽重试的记录；统计所需全量查询不变。首屏同时加载状态与列表，设置/任务直达页不重复加载状态。

延长生产观察发现第二处热点：释放空名额会逐次同步唤醒背调，每次扫描全量公司；缺失公司链接还会大量构造URL异常。CPU采样确认栈来自MatchScheduler的onAvailable→CompanyResearch.tick/run→companySubject→URL。改为同一事件轮只通知一次，缺失链接直接判空、每个主体仅解析一次主页链接。没有降低并发或改变背调/采集互斥。

## 兼容性

无业务数据结构迁移，不修改保存的并发/额度/自动开关，不删除历史数据。模型依旧并发、单条完成即补位；背调互斥、活跃筛选、消息发送授权规则不变。旧版备份可回退。未自动发布GitHub。

## 验证

覆盖16路空队列单次检查、无关写入不失效、跨连接相关写入失效、策略变更、时间重查、SQL候选筛选，以及现有并发/额度/重试测试。浏览器验收检查慢状态响应时列表独立请求、任务/设置初始状态请求只发一次及四页/列表/抽屉回归。数据副本测试不调用真实模型，不发送HR消息；本机实测记录见验收文档。

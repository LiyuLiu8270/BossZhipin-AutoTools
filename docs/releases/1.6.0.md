# 1.6.0 — 独立匹配与招呼生成

## 使用

- 自动任务：分别开启或暂停“JD 自动匹配”“自动生成招呼”；设置 → 自动化与额度也提供两个独立勾选项。
- 只开匹配：生成匹配结论，不生成草稿。只开招呼：使用现有合适岗位匹配结论，不启动新的匹配。
- 岗位详情 → 沟通记录 → “重新生成打招呼”：按当前简历、匹配结论和招呼风格单独排队一次；不开启自动开关、不改匹配、不发送。仅限优先沟通／可以尝试、有效且符合活跃条件的岗位。
- 手动和自动任务共享并发及每日额度。额度用完则排队，旧成功草稿保留至替换成功；失败可再点击生成。关闭自动生成不取消已明确提交的手动请求或在途任务。
- 旧单开关配置在首次加载时让两个开关继承原值，避免升级擅自扩大或缩小已授权的自动范围，后续各自独立。

## 采集修复

详情身份校验失败不写入错误数据，本轮跳过并继续其他岗位。失败至少间隔一小时后可重试，累计三次移至待复查，避免反复卡在同一游标。登录失效、验证码、浏览器不可用仍暂停整批，不尝试绕过。

本地任务日志和逐操作日志增加身份校验阶段、预期 URL、实际页面 URL、解析 URL 及空值标记；不记录 query、fragment 等访问参数。无法读取的地址明确为空，不伪称真实跳转。

无数据库表结构迁移，不删除用户岗位、人工记录、匹配或历史背调，不改变 AI 聊天接管规则。未推送或发布 GitHub。

# 1.1.0：效率列表与待办优先

本地实现版本；版本号不代表已推送 GitHub 或创建远端 Release。

## 使用变化

岗位机会默认展示值得沟通岗位；有 HR 未读提醒或未知发送时，到“待我处理”集中处理。普通待回复在“沟通中”，不会被误认为新回复。需要完整库时选“全部岗位”。

搜索、月薪和招聘者活跃保留在列表上方，其余在“更多筛选”。详情侧栏用四个标签分别承载匹配、公司背调、原文、沟通；底部始终保留可执行沟通操作。公司背调已具有独立入口，不再挤占匹配首屏。

自动任务保留进度及常用操作，计划、维护和历史日志按需展开。设置分成“自动化与额度”“匹配与招呼”“运行与导出”，不自动保存或自动应用预设。

## 数据与授权

不迁移表、不删除数据，不更改既有自动开关、关键词、额度和模型。待办计数基于真实持久沟通事件，查看不会自动确认已读。所有真实发送仍须逐岗授权；未知发送不重发。未保存设置在同页面切组保留，离开/刷新提示；沟通备注关闭前提示。

升级通过正常停止等待在途任务，再启动新版；升级不等于新授权，不对未授权岗位开启沟通。当前运行记录与配置需要在切换后核对。

## 验证方式与边界

`npm.cmd test`、`npm.cmd run check`、`node scripts/verify-usability-live-ui.mjs`；界面验收使用隔离数据库与独立 Edge，覆盖四页、1366/1920/410 宽度、过滤分页、详情标签、未保存提示和合成沟通授权/接管。

截图与报告保存在被忽略的 `artifacts/usability-production/`。无真实 HR 测试消息，无真实模型调用；这不等于重新验证 BOSS 端到端稳定性。

# 版本与发布维护

## 单一版本源

`package.json.version` 为唯一版本源，遵循 SemVer。发布同步 `shared/core.js` 的 VERSION 与 `desktop/TrayApp.cs` 的 AssemblyVersion（末尾补 `.0`）。网页/API从核心版本读取，不再靠URL里的build参数判断服务版本。

每次更新须同步 CHANGELOG、产品与架构、相关专题和 `docs/releases/<version>.md`。历史发布说明不覆盖，新版本记录新增、修复、数据迁移、兼容限制及分层验收。`npm run check` 验证版本一致与当前发布说明存在。

## 发布前

1. `git status --short`，保留已有改动；不将个人数据当样例。检查`.gitignore`，不提交local/data、浏览器profile、密钥、简历、日志或生成报告。
2. 运行 `npm.cmd test`、`npm.cmd run check`、受影响Python测试及 `npm.cmd run build:desktop`。网页变更另跑合成UI验收。记录真实平台/模型的授权、范围、成功与未验证项。
3. 暂停原服务，等待在途任务结束，对原SQLite做一致性备份；保留原配置和人工记录。不能以复制运行中主sqlite文件冒充完整备份。
4. 升级后验证运行版本、岗位/人工记录不变性、原定时与模型设置、托盘和页面。跨目录旧实例迁移单独执行，不自动复制个人数据库或登录态到开源目录。
5. 查看完整 `git diff` 和待提交文件清单，再提交本版本。发布产物仅含代码和许可，不能打包整个工作目录。

# 产品与架构

适用版本：1.7.1。版本源为 package.json；当前发行变更见 CHANGELOG 与 docs/releases。

1.7.1 为发布验证与启动修订：模拟流水线显式注入模型运行环境替身；Windows CI 测试文件串行运行，测试内部的并发断言保持不变。托盘逐个验证 Node 候选版本，系统目录旧版或损坏时继续尝试 PATH 中可用的 24+。无模型业务逻辑、数据库或用户设置变更。

## 1.7.0 固定优先级模型准入

后续招呼调整：草稿采用纯文本调用，模型最终正文不经结构、字数、claims、事实编号或引文校验直接保存。存储保留空 claims/greeting_fact_ids 以兼容读取；completed 仅表示模型执行完成，不表示语义核验。请求异常、空响应、并发额度与版本隔离仍保留。以下历史章节中的草稿输出核验约定已被此调整取代；AI 聊天校验及人工接管不变。既有失败记录不自动重排，用户可通过批量重新生成重试。

- WebController.modelQueue 是服务内模型任务共享准入点。匹配/招呼和背调以可执行来源注册；真实沟通和简历全文分析以单次请求排队。在请求实际执行前占用名额，完成或异常后释放，不等待整批。
- 固定顺序：已识别的 HR 回复（0）→ 人工重新生成招呼及简历分析（10）→ 真实首次沟通（20）→ 自动招呼草稿（30）→ JD 匹配（40）→ 自动公司背调（50）。同优先级先等待者优先，没有等待补偿、动态提权或在途抢占。后台可因前序任务持续积压而等待。
- 只要存在已授权、状态 queued/watching 的沟通任务，总并发大于 1 时预留一路供 hr_reply/chat_greeting；后台以及人工批量重写不得借用。总并发为 1 时不预留，等待当前任务结束。新授权发生时已运行任务不取消，名额随完成释放。
- 优先级作用于已经就绪的模型请求，不代表未读 HR 消息已经被发现；浏览器会话读取继续串行，已运行的首条招呼不被后来消息抢占，发送前仍重新核对消息和授权。人工接管逻辑不变。
- 简历全文评分/岗位方向解析与其他模型任务共享每日额度，等待期间不扣费，真正领取时原子记一次任务预算；无额度直接反馈失败，不更改额度或设置。
- 源队列领取前重新检查开关、额度、活跃条件和资格。关闭时停止新领取，取消未开始的单次请求，保留持久化匹配/招呼/背调队列；等待已开始请求结束。
- /api/state.modelScheduling 暴露占用、分类、沟通预留及等待时长（时长只用于展示，不参与优先级）。

## 1.6.1 批量招呼与采集时间

- 后续交互调整：任务页使用五个互斥 tabpanel（岗位采集、匹配与招呼、批量生成招呼、公司背调、搜索关键词），通过 hidden 切换而不重建表单。切换不保存、不调度；主页面来回导航保留当前标签和输入。
- JD 匹配/自动招呼开关仅在任务页控制。设置页只提交额度、并发和活跃规则，并合并保存时的最新配置，不带旧开关草稿；跳转任务按钮直接选中对应标签。

- 批量操作按当前简历版本的匹配结论与可用 JD 选取，四档可多选、数据集可限定，默认排除已沟通，沿用活跃条件。预览不修改数据，提交时核对范围/版本/草稿状态指纹后事务入队，不重启运行中的生成。
- 手动批次使用 requested 队列，不开自动开关也会执行；共用并发、额度和原文依据校验。低档只在显式请求后进入，不扩大普通自动候选。
- collected_at 为有效 last_seen_at 与 jd_observed_at 的最大值。列表展示北京时间日期、时分秒；不回退到匹配、导入或岗位发布时间。

## 1.6.0 独立自动阶段与详情异常隔离

- settings.autoAnalyze 只控制 JD 匹配，autoGreeting 只控制招呼草稿。旧配置缺少 autoGreeting 时继承旧 autoAnalyze 值保持升级行为，之后独立保存；新安装均默认关闭。
- 共用原并发池及额度，调度器每次领取时读取阶段开关，关闭不杀在途。greeting_runs.state=requested 表示单岗位手动请求，自动开关关闭也排队一次；重复请求幂等，运行中拒绝重复。仅针对已匹配合适且允许处理的岗位，不发消息或改匹配。原成功草稿保留至新结果通过核查。失败后自动重试受招呼开关控制。
- 详情 detail_page_changed 改为单岗位失败，保留正文、不写错岗数据；游标继续，1 小时后可再试，累计三次转 review。登录、验证码、浏览器不可用及搜索页异常仍全局暂停。重试采集实际占用详情额度。
- Python detail_identity 记录校验阶段、预期/实际/解析地址及空地址标记，去除 query/fragment；Node 逐岗记录尝试数、入库校验失败、下一游标及待复查状态。日志留本地，不包含访问参数。

## 1.5.1 简历全文分析复用 Skill

- 岗位解析、简历评分从同一 matchingPolicy.matchingSkill 读取已保存方法，开始时冻结输入；当前 Word 全文仍为事实来源，打招呼风格不参与评价。
- 分析记录保存 Skill 指纹和是否应用；当前 Skill 或分析版本不同则显示历史结果待重新分析，不自动删除、重跑或启用推荐关键词。空 Skill 使用默认方法。

## 1.5.0 公开浏览器背调

- 背调向 Codex 临时注册 xunxu_public_browser MCP，仅 browser_search/browser_open；不再强制原生搜索，不开放 shell、私人浏览器或其他连接器。匹配、招呼及聊天的工具边界不改变。
- 独立 Edge 临时 profile 通过公网地址校验及 DNS 地址固定代理访问外部资料，与 BOSS 采集 Edge、招聘会话隔离。模型自定关键词、引擎和网页，不按公司编排搜索流程。
- 每页证据记录请求/实际 URL、渲染正文与链接、读取时间和验证提示；防止导航尚未提交时误读上一页。模型输出保持 Markdown 原文，不用简单覆盖公式替代语义判断。
- 归档原生搜索旧阻断以允许新能力首轮探测；新故障仍持久阻断，不篡改用户开关或删除报告。

## 1.4.1 提醒来源及模型格式快照

- 模型生成首条招呼的handoff与实际新消息分开：greeting_handoff/reply_handoff保存原因、来源和关联消息ID。仍按原逻辑暂停，不改变needsHuman或事实校验规则。
- comm_event_context为事件保存说明及待办去重键，同一生成阶段、同一消息集合/简历/风格的已读待办不因重复开启而重新变成未读。不删除历史记录，不把转人工当作HR回复。
- 匹配/招呼/聊天/简历评价的schema在模块加载时固定，按内容哈希写到本地工作目录供CLI读取；运行中的旧校验器不会因磁盘升级读到新版schema。简历评价记录版本、schema_hash、请求ID、失败阶段，不记录原始敏感输出。
- 旧版失败评价显示“旧版本的失败记录”，提示用当前版本重新分析，不再误写“未同步关键词”。

## 1.4.0 AI 语义判断边界

- 匹配仍输入当前简历全文、JD、匹配 skill，保留 AI 原始档位、理由、缺口；软件仅校验身份、结构和原文出处，不做关键词匹配评分。
- 招呼仍在匹配之后独立生成，风格只影响表达。允许同义概括、等值数字表达，由 AI 对完整上下文核查职责、成果与频次；程序不以主导/持续/数字的字面出现决定语义是否真实。引用编号、原文出处及输出结构仍校验。招呼版本更新，不重算既有岗位匹配。
- 简历评价由 AI 选择维度和整体参考分，可定性评价，不再固定五项20分相加；搜索关键词只建议，人工点击“加入采集”才启用。
- 公司背调仅传工商全称与任务，单次 Codex 原生联网自主生成报告；删除旧 search/open 编排和固定覆盖公式，保留旧报告查看。任务完成不等于软件独立核实事实。
- 新增 company_research_runtime 存储联网能力阻断；首次一路探测，成功后按配置补位，明确技术故障持久暂停后续背调，详情“重新背调”重试能力。其他模型任务不受影响，用户开关不被改写。
- AI聊天人工接管、敏感承诺、未知发送及原有聊天审核规则保持不变。

## 1.3.3 公司名称搜索

- 搜索岗位、招聘显示名、地区及platform_verified且绑定本岗位/公司页的工商全称。索引按intake_jobs代数缓存，不依赖模型更新。
- 同数据集、同BOSS公司主页、唯一已核实全称时共享该组显示名和全称；多主体只保留各岗位自己的证据。禁止仅凭同名或相似名称跨公司关联，猎头/代招/冲突记录不传播。
- NFKC、大小写、空白归一仅用于检索；不写回原始数据、不修改匹配结论或背调主体，不增加联网/模型调用。现有筛选和分页口径不变。

## 1.3.2 页面响应与调度

- 异步模型阶段之前同步领取匹配/招呼任务并保存空队列检查结果，防止同轮并发槽重复扫描。真正的模型任务仍并发执行，单条完成立即补位。
- 空队列按岗位、分析队列、匹配、招呼表代数与资料/规则失效，无关采集进度或报告写入不失效；最长5秒重查处理时间边界。跨连接写入相关表亦通过持久代数触发失效。
- 招呼领取SQL仅返回可执行候选，状态统计仍保留全量。首屏状态与列表并行，任务/设置页面首次进入复用同一状态请求。
- 同一事件轮释放多个名额时只通知兄弟队列一次，不等待任何模型任务成批完成。公司主页链接缺失直接判空，主体键算法不变，避免热路径反复构造URL异常。
- 不修改并发设置、预算、招聘者活跃条件、公司背调与采集互斥、真实消息授权。

## 1.3.0 工商主体基线

- 详情采集的共享 DOM 解析器读取独立工商区 company_identity，Python 边界透传并由适配器按岗位URL绑定保存；不覆盖 company 显示名，不修改匹配输入指纹。
- 背调先复用同岗位工商全称，无证据才在专用 Edge 单路读取关联公司主页并缓存；缺失/冲突不调用模型，不消耗模型额度。平台主体不等于签约主体。
- v3 报告键优先按公司主页隔离，同名不同主页不复用；旧v2报告保留但不再自动采用，新版队列重新核查身份。详见 releases/1.3.0.md。

## 1.2.0 背调调度基线

- 自动任务增加公司背调分类入口、状态/队列/在途公司、并发选择和暂停/继续；设置页只保留跳转，不创建两套开关。
- `companyResearch.concurrency` 为0（跟随全局，旧配置缺省亦同）或1–16的背调上限；有效上限取背调/全局两者较小值。保存仅开关时保留原并发，不改写autoAnalyze或其他额度。
- 每公司任务从领取到证据核验完成持有一个名额；`running`按公司键维护。匹配、招呼、AI沟通、背调共享全局总并发和每日任务额度；领取时同步预占，完成即归还并唤醒补位，不等待同批慢任务。同公司不会并发重领。
- 变大即时补位，变小等待占用自然下降；暂停/正常停服阻止新领取，所有在途任务继续保存，close等待全部在途结束。各公司Codex诊断写在各自公司键目录，来源与观察数据保持任务隔离。
- 既有串行背调升级后默认跟随已配置的模型总并发，会提高并行度及单位时间模型/检索负载；总并发和每日额度数值本身不变。

## 1.1.0 交互基线

- 四页为岗位机会、自动任务、我的简历、偏好与设置；岗位保留列表＋抽屉，不采用卡片墙。
- 默认值得沟通：优先沟通/可以尝试，未标记已沟通、未结束/忽略、无关闭/不可用证据且没有在运行或未知发送的沟通任务。沟通未知仍不代表未联系，发送前需核对。
- 待我处理仅按未读沟通事件或未知发送判定，不把所有“已回复”或“待回复”作为未读；查看不自动确认已读。未知发送核对前持续在待办中。待办允许包含已忽略岗位的未解决事件。
- 全部/值得沟通/待办/沟通中在服务端全量过滤后分页；计数按数据集统计，不随其他筛选变化。切换视图清除其他筛选但保留数据集/排序；普通筛选在当前视图内叠加，条件可单独移除。
- 详情分匹配、背调、原文、沟通四标签，底部固定逐岗授权与人工接管；查看、筛选、切页无发送副作用。未知发送不能再次发起，运行中不能重复授权，已联系不提供重复首次招呼。
- 任务计划、维护操作和日志折叠；设置按自动化与额度、匹配与招呼、运行与导出分组，各自显式保存。设置草稿切组保留；离开提示，刷新提示；沟通备注关闭前提示。
- 不改数据库结构，不自动改写用户的自动分析、背调、定时、额度和关键词。合成 UI 验收脚本为 scripts/verify-usability-live-ui.mjs，不运行真实采集/模型/消息链路。

## 产品范围

四页：岗位推荐、采集与任务、我的资料、设置。列表＋抽屉为主。软件负责采集、去重、匹配、公司背调和本地记录；本人负责登录、验证、选择岗位。逐岗位明确授权后可由AI发送普通求职文本，或本人联系HR；不自动投递附件、不替本人承诺薪资/面试时间。

## 1.0.0 新增链路与基线

- 当前有效匹配为优先沟通/可以尝试，未忽略、未结束、未观察到岗位终止 → 公司键 → 持久背调队列 → Codex原生联网任务 → Markdown报告保存及展示。原 search/open 编排已于1.4.0移除。
- 法定名称不去后缀、不与母子公司合并；全称按名称复用，简称按名称＋城市隔离且保守标主体待核实。猎头/代招/冲突徽标不将代理公司当雇主。
- SQLite `company_research` 保存键、状态、尝试数、下次时间、当前报告与错误；成功/待核实缓存30天，瞬时模型故障最多3次、间隔至少1小时；手动重排60秒冷却。刷新失败保留旧报告，界面显示当前失败与旧时间。重启running重排，原匹配/简历/人工记录不变。
- 原网页、JD和模型输出是不可信数据，不是执行指令。背调使用原生web_search，单次配置关闭shell、插件/连接器及已配置MCP，出现非预期工具事件则失败；匹配与聊天不增加工具权限。报告以安全文本呈现，不执行HTML，不携带浏览器登录态。
- 公司资料不代表岗位匹配结论，报告不会自动发送给HR，也不改变匹配档位。未查到风险、规模、工商资料只代表证据缺口；来源引用存在不能完全证明模型语义正确。
- 背调预占现有模型槽和每日任务预算；1.2.0起多路并发，1.4.0首次增加单路联网能力验证。自动背调独立开关默认开启，不更改autoAnalyze；每次尝试计一次任务预算，内部模型调用及检索次数由Codex决定。原手动简历诊断仍独立。
- `GET /api/company-research` 返回指定岗位共享报告；`/report` 返回Markdown及结构化报告；`POST /retry` 重排；`POST /settings` 保存开关。继承全部同源鉴权，不提供任意URL抓取API。
- 逐岗AI沟通：独立自有Edge页面、稳定账号/岗位/招聘者ID、消息ID去重、持久发送意图；新文本触发普通自动回复或只打招呼后的提醒。非文本只提示人工查看；身份冲突、人工插话、敏感承诺和未知发送暂停。`comm_threads/messages/events` 不与公司报告混存；详见 `local/COMMUNICATION.md`。
- 运行依赖均在仓库内，公共背调网络层仅使用Node内置模块；vendor及Python主采集不修改。工程仍是Windows本地软件，不是全平台或无人值守承诺。

采集不按简历预先丢弃岗位。岗位身份为数据集＋平台 ID；重复采集保留人工状态和历史证据。描述非空且通过页面身份、门禁、就绪及稳定校验即算采集完成，短正文不因此反复抓取。关闭与链接不可用保留独立证据，顶部按用户可理解的互斥口径汇总：收录＝已采集＋关闭/不可用＋待采详情。

招聘者活跃筛选累计包含更近期等级，未知和历史证据独立；自动匹配可配置跳过不活跃条件。Word 原件本地解析留存，匹配仅使用当前全文。匹配和招呼分阶段，共享并发令牌与每日预算；改招呼风格不重评匹配。

## 组件

- `desktop/`：Windows托盘，启动/接管本项目服务和正常停止。
- `local/automation.mjs`：服务及维护入口，监听127.0.0.1:17321。
- `local/collector.mjs`：手动/定时采集、详情/补采队列、每日额度和恢复游标。
- `local/scraper-bridge.py`：子进程边界，加载 `vendor/boss-zhipin-scraper/scripts/boss_cdp_raw.py`，连接本机19222的专用Edge。
- `local/runtime-paths.mjs`：项目内 `.venv` 和 `local/data/edge-profile`；可用 `BOSS_TOOLS_PYTHON` 指定绝对解释器路径。
- `local/intake.mjs`：SQLite及原文/历史保存；`shared/`：身份、字段、可见页面和质量规则。
- `local/worker.mjs`、`match-scheduler.mjs`：模型任务、并发、重试、预算与结果校验。
- `local/web/`：四页交互；Web API采用本机同源会话、Host/Origin与请求头校验。管理健康/停止接口使用私有服务令牌。

## 调度和缓存

定时默认关闭，间隔默认360分钟，详情每日默认30次。每日计数按北京时间换日、跨轮累计，不因重启清零；失败请求也可能计入。平台限制不可用额度规避。登录/验证码等门禁需人工处理后恢复，普通详情失败有限重试、至少间隔一小时。服务休眠/停止时不会执行。

自动匹配默认关闭；模型预算按匹配/招呼尝试分别计数。额度耗尽停止空转，保留队列及开关。派生统计按依赖表代数、规则、资料和退避时间失效；正文缓存与模型写入分离。列表在快照内筛选分页，抽屉按单条身份查询；报告最多合并30秒写入，结果即时入库，正常退出刷新报告。

# 开源采集器字段对齐约定

适用：eatmoreduck/boss-zhipin-scraper 2.3.0（验证提交 `46e2965de42c6c44a18021c1f8602a62b838297c`）。
入口：`IntakeStore.importScraper({list, details, label, timezoneOffset, detailsObservedAt?, observationId?})`。
数据适配已连接开源采集进程及网页任务调度，见 [产品与架构](产品与架构.md)。以下字段隔离验证记录是适配阶段的结果，不代表后续在线采集量。

## 字段映射

| 上游字段 | 本地字段 / 处理 | 含义及边界 |
| --- | --- | --- |
| `encrypt_job_id`、`job_link` | `job_id`、`id=boss:<平台ID>`、`url` | 平台岗位身份；交叉核验后去重，链接去查询参数 |
| `job_id` | 原样保存在 `scraper_source` | 上游链接散列，不替换本地平台 ID |
| `title` | `title`、`title_list_raw` | 岗位标题；同 ID 标题冲突保留旧业务数据，写入 `scraper_review` |
| `salary`、`salary_source` | 同名字段 | 薪资原文及来源，不计算未经确认的年包 |
| `location` | `location`、`locations` | 城市/区域展示文本，不反推精确地址；不以较粗地址覆盖旧详细地址 |
| `tags` | `requirements_raw`、`experience`、`education`、分类标签 | 仅拆分明确的经验学历文本；上游会过滤“不限”，空值不能解释为不限 |
| `boss_name` | `company`、`company_raw`、`company_display_name` | 实际来自品牌展示名，不是招聘者姓名，也不保证是工商全称 |
| `boss_title` | `recruiter_title` | 招聘者职务，不是岗位标题 |
| `boss_active_status` | `scraper_activity_observations` | 保存活跃原文和批次时间；已接入网页及报告的活跃展示，不据此推断岗位关闭 |
| `company_scale`、`company_stage`、`company_industry` | 同名字段 | 公司规模、融资阶段、行业 |
| `encrypt_brand_id`、`company_link` | `company_id`、`company_url` | 公司展示实体 ID 和链接；缺失保持空，校验域名及 ID 一致性 |
| `encrypt_boss_id` | `recruiter_id` | 招聘者加密 ID，不是姓名 |
| `job_labels` | `job_labels`、分类标签 | 保留原标签，并沿用本地福利/薪酬标签分类 |
| `skills`、详情 `skill_tags` | `skills`、分类标签 | 合并去重，移除明确的网站噪声词（如 kanzhun）；保留原始来源 |
| `welfare` | `benefits` / `compensation_tags` / `tags` | 按现有标签规则分类，完整原文仍保留 |
| `security_id`、`lid` | `scraper_access` 及原始来源 | 访问上下文，不参与岗位去重，不发送给模型，不写入公共日志 |
| `is_new` | 原样保存在 `scraper_source` | 相对上游文件基线的新记录，不代表新发布；本地新增按数据集和岗位 ID 判断 |
| 详情 `jd` | `jd_raw`、`jd`、`jd_status`、`jd_truncated` | 保留原文；仅剔除精确命中的末尾招聘许可证模板；可读不等于已证明完整 |
| 详情 `company`、`title`、`salary`、`salary_source`、`location`、`tags_list` | 原样保存在 `scraper_source.detail` | 多数由列表复制，不当作详情独立复核；同义业务字段以列表为准 |
| 详情 `job_id`、`job_link`、`link` | 身份校验并保留原始来源 | 不允许详情串到另一岗位 |
| `keyword`、`city`、`filters`、`filter_desc`、`scraped_at`、`total` | `scraper_source.batch`、`scraper_batch`；关键词合并到 `keywords` | 搜索批次信息，不是岗位属性；total 不作为实际导入计数 |

全部列表/详情原始字段（包括未来新增字段）保存在 `scraper_source.list/detail`，并通过 `intake_versions` 留存版本。
0.12.1 自动列表隔离的异常行不进入岗位库或版本表，其原文仅保留于该轮私有桥接输出；运行记录另留原始零基行号与原因。岗位 ID 支持字母、数字、下划线、横线及波浪号。自动预处理仅合并完全相同的重复行，同 ID 不同内容整组隔离；严格适配入口仍拒绝重复或身份冲突。
这些原始对象含访问上下文，不能直接用于公开报告或整包发送给模型。

## 时间与活跃状态

- `scraped_at` 没有时区时，调用方必须明确传入 `timezoneOffset`。中国本机试采使用 `+08:00`，适配器不偷偷假设时区。
- 列表批次时间映射首次/最近发现时间；合并保留最早首次时间和最新最近时间。它不是发布日期。
- 详情批次时间由调用方显式传入 `detailsObservedAt`，未提供则 `jd_observed_at=null`，不伪造精确采集时间。
- 上游详情活跃字段可能回退列表值：两者相同不生成“更新的详情观察”。无时间的详情活跃原文保留但不提升为当前状态。
- 未提供活跃标签不抹掉旧证据；网页注明批次时间和历史记录，不把未知说成不活跃。
- `activity_check.state=not_displayed` 仅表示：同一岗位的招聘者主区块完整、12 次有界观察结束，且没有可见活跃标签或未适配的标签文本。`reason=recruiter_panel_without_activity`；仍展示未知，不能解释成离线。区块不完整、等待未结束、未知标签仍为 `needs_review`，未知时间文案记 `activity_label_unrecognized`。
- 活跃解析 v2 接受“半年前活跃”、数字/中文数字月年描述等短标签，原文与观察时刻原样保留，不换算成猜测的最后登录日期。DOM 诊断只留区块就绪与受限标签证据，不留招聘者姓名。
- 继续沿用既有“活跃补采不单独触发模型重算”的规则。公司规模/融资/行业、明确经验学历和技能作为可选匹配输入；原始来源、访问参数和招聘者 ID 不进入模型输入。

## 保留本地工程字段

以显式白名单更新上游业务字段，其余保留：人工沟通状态、猎头/代招识别及证据、关闭/链接不可用证据、发布时间/更新时间原文、公司/活跃补采结果、详情复查、首次发现记录，以及其他本地自定义字段。

- 公司匿名描述不覆盖已知公司名称，也不据此推断猎头或代招。
- 空值不覆盖旧 JD、公司、薪资和状态证据；更旧列表不回滚主业务字段。没有时间的不同 JD 不替换已有可读 JD。
- 旧的完整导出缺少新增适配字段时，不删除已保存的新增字段。
- 人工记录和模型结果表不被适配器直接改写。匹配相关输入变化会按现有规则排入分析队列；重复相同输入不重复排队。
- 这不是补齐所有源能力：开源输出没有明确猎头徽标、关闭提示、回复标签或发布日期时，新岗位仍未知，旧岗位保留既有证据。

## 验证边界

- 回归测试：`node --test tests/scraper-adapter.test.js`；全量测试：`npm test`；语法检查：`npm run check`。
- 实际试采 JSON 隔离导入：30 个岗位、3 份可读详情，3 条待分析、27 条缺 JD 暂缓；相同输入重复导入返回 already_imported。
- 正式库只读取同 ID 的 30 条记录，复制到内存后模拟合并；沟通、招聘类型、链接、复查、公司/活跃检查、首次发现和原信号字段均保留。正式库未写入。
- 本次未进行新的在线采集，不构成长时间无人值守稳定性验证。

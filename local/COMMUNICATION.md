# AI 沟通模块

## 使用

1. 已导入当前 Word 简历、采集专用 Edge 已登录 BOSS。
2. 岗位列表或详情点击 **AI托管** 或 **只打招呼**。这是对该岗位真实沟通的授权，不是仅生成草稿；未点的岗位不发送。
3. 打开详情的“AI沟通 / 沟通记录与运行提醒”，查看消息、处理状态和未读提醒。已有会话不会再次发首次招呼；新建联系可能由BOSS先发平台默认招呼，系统再发送AI说明。
4. “只打招呼”收到新回复即暂停，控制台提醒，托盘也尝试通知。AI托管会继续处理普通文本问题；需要本人决定、发送联系方式/附件或信息不明确时暂停提醒。
5. 点“暂停 / 人工接管”阻止后续自动发送。已经提交平台的消息无法撤回。到BOSS人工发言也会在下次读取时使自动沟通暂停。

## 状态与恢复

- 等待处理：服务将在串行沟通队列里处理。
- 后台监听中：按每岗至少30秒检查，岗位数与页面耗时会增加间隔。仅保持服务和专用Edge即可，不需前台焦点；托盘不要退出。
- 已暂停：查看具体原因。登录/验证码由本人处理；简历变更、模型失败或需要人工决定时核对后重新点模式按钮。
- 发送结果待核对：发送意图已落盘但未确认送达，按钮锁定，重启不会重发。可点“核对发送结果（不重发）”；只对已有稳定身份的未知文本寻找新消息ID、精确正文和送达证据。确认后保持人工模式，再由本人选择是否开启。平台首次招呼未知或找不到回执时继续锁定，不能靠反复点按钮解锁。

## 数据与模型

SQLite新增 `comm_threads`、`comm_messages`、`comm_events`，不清旧岗位或简历。沟通记录只留在私有数据库和同源页面，不加入公开报告；模型收到当前Word解析文字、当前岗位字段和最多50条已存近期消息，手机号/邮箱会遮蔽，但不是完全匿名。不发送Cookie、访问参数、附件或完整收件箱。

沟通模型与匹配共享每日预算和并发容量，自动匹配开关不控制已授权沟通；暂停沟通应在对应岗位操作。每线程20次AI文本发送后保护暂停。缺模型容量等待，预算耗尽/生成或核查失败暂停，不无限消耗重试。

## 维护与限制

- 真实通道代码：`boss-cdp.mjs`、`boss-chat-port.mjs`；持久调度：`communication.mjs`；模型：`chat-model.mjs`。
- 消息只覆盖已渲染近期文本，附件等仅占位，发现历史缺口暂停；不保证恢复离线期间全部消息。
- BOSS DOM及选中会话字段可能变化。解析/稳定ID不完整则暂停，不自动猜测或切到另一个HR。
- 托盘提醒受Windows设置影响；未读提醒会一直留在控制台。退出托盘、服务停止、电脑休眠不能继续监听。
- 没有自动发送简历附件、交换联系方式、安排面试或接受offer；“全托管”只覆盖有事实与授权依据的普通求职文本交流。
- 独立仓库1.0.0验收以 [报告](../docs/验收-1.0.0.md) 为准，合成消息测试不代表真实HR已回复。
